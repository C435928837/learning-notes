## 2. AOP 是什么

AOP（Aspect-Oriented Programming，面向切面编程）用于将日志、权限、事务、异常记录、耗时统计等通用能力，从核心业务代码中抽离并统一处理。

例如，`ProductService.getProduct()` 的核心职责是查询商品：

```java
public String getProduct(String productId) {
    return productRepository.getProductById(productId);
}
```

记录方法名、统计耗时不属于“查询商品”本身，却可能出现在商品、订单、库存等多个模块中，因此适合使用 AOP。

### 横切关注点判断标准

> 这段逻辑是否会重复出现在多个不同业务方法中，并且不改变各自的核心业务规则？

- 是：可考虑 AOP，例如日志、权限、事务、耗时统计。
- 否：保留在业务服务中，例如库存是否充足、订单金额计算、优惠券是否可用。

## 3. AOP 五个核心术语

以 `ProductService.getProduct("P001")` 为例：

| 术语 | 含义 | CloudMall 示例 |
| --- | --- | --- |
| `Target` | 被增强的原始对象 | `ProductService` |
| `JoinPoint` | 可以插入增强逻辑的位置 | `getProduct()` 这次方法执行 |
| `Pointcut` | 筛选哪些连接点需要增强的规则 | 所有 `ProductService` 方法 |
| `Advice` | 实际执行的增强逻辑 | 前置日志、耗时统计 |
| `Aspect` | 切点与通知组成的完整模块 | 商品查询日志切面 |

关系：

```text
Aspect
  ├─ Pointcut：拦截 ProductService 的方法
  └─ Advice：打印方法名、统计耗时
```

Spring AOP 中，`JoinPoint` 可以理解为所有可能拦截的方法执行点；`Pointcut` 是实际选中的方法规则。

## 4. 通知类型

| 通知 | 执行时机 | 常见场景 |
| --- | --- | --- |
| `@Before` | 目标方法执行前 | 参数校验、权限校验、开始日志 |
| `@AfterReturning` | 方法正常返回后 | 记录返回结果 |
| `@AfterThrowing` | 方法抛出异常后 | 异常日志、告警 |
| `@After` | 方法结束后，无论成功或异常 | 清理资源 |
| `@Around` | 包裹整个方法执行过程 | 耗时统计、事务、统一异常处理 |

`@Around` 中必须调用：

```java
joinPoint.proceed();
```

否则真实目标方法不会执行。

## 5. CloudMall AOP Demo

### 5.1 切面代码

```java
@Aspect
@Component
public class SpringAopDemo {

    @Pointcut("execution(* com.cloudmall.demo.spring.ProductService.*(..))")
    public void productServiceMethods() {
    }

    @Before("productServiceMethods()")
    public void logBefore(JoinPoint joinPoint) {
        System.out.println("调用方法：" + joinPoint.getSignature().getName());
    }

    @Around("productServiceMethods()")
    public Object methodsTime(ProceedingJoinPoint joinPoint) throws Throwable {
        long startTime = System.currentTimeMillis();

        try {
            return joinPoint.proceed();
        } finally {
            System.out.println("方法耗时："
                    + (System.currentTimeMillis() - startTime));
        }
    }
}
```

### 5.2 切点表达式

```java
execution(* com.cloudmall.demo.spring.ProductService.*(..))
```

含义：

- 第一个 `*`：返回值不限。
- `ProductService`：目标类。
- 第二个 `*`：类中任意方法。
- `(..)`：参数不限。

### 5.3 执行流程

```text
CommandLineRunner
  ↓
ProductService 代理对象
  ↓
@Before：打印调用方法
  ↓
@Around：开始计时
  ↓
真实 ProductService.getProduct()
  ↓
@Around：打印耗时
  ↓
返回商品信息
```

预期输出：

```text
调用方法：getProduct
方法耗时：约 3000
P001商品
```

### 5.4 运行前提

`pom.xml` 需要加入：

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-aop</artifactId>
</dependency>
```

## 6. 代理机制

Spring AOP 通过代理对象，在目标 Bean 方法调用前后插入增强逻辑。

### JDK 动态代理

- 基于接口创建代理对象。
- 目标类通常需要实现接口。
- 调用方应按接口类型使用对象。

### CGLIB 代理

- 基于继承，为目标类创建子类代理。
- 目标类不要求实现接口。
- `final` 类和 `final` 方法无法被继承或重写，因此不能被 CGLIB 增强。

## 7. 高频失效边界

### 7.1 同类自调用

```java
public void queryProduct() {
    this.getProduct("P001");
}
```

`this.getProduct()` 没有经过代理对象，AOP 通常不生效。

优先方案：拆分到另一个 Spring Bean，通过跨 Bean 调用触发代理。

### 7.2 手动 new 对象

```java
ProductService productService = new ProductService();
```

手动创建的对象不是 Spring Bean，没有代理，AOP 不生效。

### 7.3 不适合代理的方法

- `final` 类
- `final` 方法
- `private` 方法
- `static` 方法

需要 AOP 增强的业务方法，通常使用非 `final` 的 `public` 实例方法。

## 8. 权限校验场景

权限校验属于横切关注点，可以在方法执行前统一处理：

```java
@RequirePermission("product:create")
public void createProduct(String productName) {
    // 创建商品核心业务
}
```

切面读取注解中的权限标识，获取当前登录用户并校验：

```text
调用创建商品方法
  ↓
切面读取 product:create
  ↓
校验当前用户是否有该权限
  ↓
有权限：执行目标方法
无权限：抛出无权限异常
```

生产项目中通常优先使用 Spring Security 的：

```java
@PreAuthorize("hasAuthority('product:create')")
```

它底层同样依赖代理和 AOP 思想，但认证、授权和异常处理能力更完整。

## 9. 面试表达

### 什么是 AOP？解决什么问题？

AOP 是面向切面编程，用于将日志、事务、权限、监控等横切关注点从核心业务中抽离。Spring 通过为 Bean 创建代理对象，在调用目标方法前后织入增强逻辑，从而减少重复代码、降低业务代码耦合。

### JDK 动态代理与 CGLIB 的区别？

JDK 动态代理基于接口，代理对象实现目标接口；CGLIB 基于继承，为目标类创建子类代理，因此不能代理 `final` 类和 `final` 方法。

### 为什么同类自调用会导致 AOP 失效？

Spring AOP 依赖代理对象拦截调用。同一个类中使用 `this.方法()` 时，调用直接发生在真实对象内部，没有经过代理对象，因此切面通常不会生效。
