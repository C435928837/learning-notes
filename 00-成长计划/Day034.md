## 2. Spring MVC 是什么

Spring MVC 是 Spring 用于处理 HTTP 请求的 Web 框架。

CloudMall 的接口请求：

```text
GET /api/products/P001
```

会被 Spring MVC 路由到对应的 Controller 方法，再调用 Service 与 Repository，最后返回 HTTP 响应。

---

## 3. 请求处理流程

```text
客户端发送 HTTP 请求
  ↓
DispatcherServlet
  ↓
HandlerMapping 查找匹配的 Controller 方法
  ↓
Controller 接收并绑定请求参数
  ↓
Service 执行业务逻辑
  ↓
Repository 查询数据源
  ↓
Controller 返回 Java 对象
  ↓
HttpMessageConverter 转换为 JSON
  ↓
返回 HTTP 响应
```

面试表达：

> Spring MVC 以 DispatcherServlet 作为前端控制器接收请求，通过 HandlerMapping 找到对应的 Controller 方法，完成参数绑定后调用 Service 处理业务，最后通过 HttpMessageConverter 将返回对象序列化为 JSON 响应给客户端。

---

## 4. 分层职责

| 层级 | 职责 |
| --- | --- |
| Controller | 接收 HTTP 请求、处理参数、返回响应 |
| Service | 编排和实现业务规则 |
| Repository | 查询或修改数据库、缓存等数据源 |

Controller 不应直接编写数据库 SQL，也不应承担订单创建、库存判断等核心业务规则。

## 5. 常用注解

### 5.1 `@RestController`

```java
@RestController
@RequestMapping("/api/products")
public class ProductController {
}
```

`@RestController` 用于 REST 接口，方法返回值会直接写入响应体，通常自动转换为 JSON。

它等价于：

```java
@Controller
@ResponseBody
```

### 5.2 `@PathVariable`

```java
@GetMapping("/{productId}")
public ProductResponse getProduct(
        @PathVariable String productId
) {
    // ...
}
```

请求：

```text
GET /api/products/P001
```

路径中的 `P001` 会绑定为 `productId` 参数。

适合：商品 ID、订单 ID、用户 ID 等资源标识。

### 5.3 `@RequestParam`

```java
@GetMapping
public List<ProductResponse> listProducts(
        @RequestParam(required = false) String keyword,
        @RequestParam(defaultValue = "1") int page,
        @RequestParam(defaultValue = "10") int pageSize
) {
    // ...
}
```

请求：

```text
GET /api/products?keyword=java&page=2&pageSize=20
```

适合：筛选、分页、排序等可选查询条件。

### 5.4 `@RequestBody`

```java
@PostMapping
public ProductResponse createProduct(
        @RequestBody CreateProductRequest request
) {
    // ...
}
```

请求：

```http
POST /api/products
Content-Type: application/json
```

```json
{
  "productCode": "P002",
  "productName": "Java 面试指南",
  "price": 99
}
```

Spring MVC 通过 `HttpMessageConverter` 将 JSON 自动转换为请求 DTO 对象。

## 6. REST 接口设计

### 6.1 URL 使用名词表示资源

不推荐：

```text
GET /getProduct?id=P001
POST /createProduct
```

推荐：

```text
GET  /api/products/P001
POST /api/products
```

资源使用名词，操作使用 HTTP 方法表达。

### 6.2 商品接口示例

```text
GET    /api/products                 查询商品列表
GET    /api/products/P001            查询商品详情
POST   /api/products                 新增商品
PUT    /api/products/P001            全量修改商品
PATCH  /api/products/P001            局部修改商品
DELETE /api/products/P001            删除商品
```

### 6.3 订单业务动作

取消订单、支付订单属于复杂业务动作，可使用：

```text
POST /api/orders/O001/cancel
POST /api/orders/O001/pay
```

## 7. 常用状态码

| 场景 | 状态码 |
| --- | --- |
| 查询、修改成功 | `200 OK` |
| 创建成功 | `201 Created` |
| 删除成功且不返回内容 | `204 No Content` |
| 参数错误 | `400 Bad Request` |
| 未登录 | `401 Unauthorized` |
| 无权限 | `403 Forbidden` |
| 资源不存在 | `404 Not Found` |
| 商品编码重复、库存冲突 | `409 Conflict` |
| 系统未知异常 | `500 Internal Server Error` |

## 8. CloudMall Demo

### 8.1 查询商品接口

```java
@RestController
@RequestMapping("/api/products")
public class ProductController {

    private final ProductService productService;

    public ProductController(ProductService productService) {
        this.productService = productService;
    }

    @GetMapping("/{productId}")
    public ProductResponse getProduct(
            @PathVariable String productId
    ) {
        return new ProductResponse(
                productId,
                productService.getProduct(productId)
        );
    }
}
```

```java
public record ProductResponse(
        String productId,
        String productName
) {
}
```

请求：

```text
GET /api/products/P001
```

预期 JSON：

```json
{
  "productId": "P001",
  "productName": "P001商品"
}
```

## 9. 面试表达

### `@Controller` 与 `@RestController` 的区别？

`@Controller` 通常用于返回页面视图；`@RestController` 等价于 `@Controller + @ResponseBody`，方法返回值会直接写入 HTTP 响应体，常用于前后端分离项目返回 JSON。

### `@PathVariable` 与 `@RequestParam` 的区别？

`@PathVariable` 用于接收路径中的资源标识，例如 `/products/P001` 中的商品 ID；`@RequestParam` 用于接收查询参数，例如分页、关键字、排序等条件。

### 为什么 Controller 不直接操作数据库？

Controller 负责 HTTP 协议相关工作，Service 负责业务规则，Repository 负责数据访问。分层后职责清晰，代码更容易复用、测试和维护。
