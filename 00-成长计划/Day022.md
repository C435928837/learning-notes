## 3. JVM 运行时数据区

| 区域 | 线程私有 / 共享 | 我的理解           | 关键边界 |
| --- |-----------|----------------| --- |
| 程序计数器 | 私有        | 记录线程执行方法时的具体位置 | 线程私有；记录当前线程字节码执行位置。Native 方法执行时没有确定的字节码位置。 |
| 虚拟机栈 | 私有        | 每个线程都有自己的虚拟机栈  | 线程私有；存的是栈帧、局部变量和对象引用，不等于“对象本身在栈中”。递归过深常见 StackOverflowError。 |
| 本地方法栈 | 私有        | 执行本地方法         | 线程私有；服务 Native 方法。具体实现可能与虚拟机栈合并。 |
| 堆 | 共享        | 存放对象和数组        | 线程共享；对象和数组通常在堆中，是 GC 主要管理区域。不要绝对说“所有对象一定在堆中”，JIT 逃逸分析可能优化分配。 |
| 方法区 | 共享        | 存放类的信息         | 线程共享；是 JVM 规范中的逻辑概念，存放类级别信息、运行时常量池等。 |

我的总结：

>JVM内存可分线程私有和线程共享两部分，其中程序计数器、虚拟机栈和本地方法栈属于线程私有，堆和方法区属于线程共享

## 4. 栈帧与对象引用

代码示例：

```java
void create() {
    Product product = new Product("P001");
}
```

`product` 局部变量在哪里：

>栈帧的局部变量

`new Product("P001")` 创建的对象通常在哪里：

>堆

方法执行结束后，栈帧发生什么：

>方法执行结束或异常退出后，栈帧从虚拟机栈弹出并销毁。

对象为什么不一定立刻被回收：

>对象可能还会被其他线程、其他对象、静态变量引用，在GC Root中可以访问，此时不能回收。即使对象已经不可达，回收仍由JVM根据内存情况和回收策略决定，不一定立即回收

GC Root 的常见来源：

- [ ] 栈帧局部变量表中的引用
- [ ] 静态字段引用的对象
- [ ] JNI 本地方法引用
- [ ] 正在运行的线程对象

## 5. 方法区与元空间

方法区和元空间的关系：

>方法区属于JVM的逻辑概念，元空间是JDK8后由HotSpot实现的本地内存存放类元数据

元空间主要保存的内容：

- [ ] 类名、父类、接口
- [ ] 字段和方法描述
- [ ] 方法字节码

堆中对象数量与元空间大小分别主要受什么影响：

>堆中对象数量受创建实例影响，元空间受类加载影响

`OutOfMemoryError: Metaspace` 的常见原因：

>动态代理等场景持续生成新类，或类加载器泄漏导致旧类无法卸载，使类元数据不断占用元空间。

需要避免的绝对化说法：

- [ ] 元空间完全等于方法区。
- [ ] 所有静态字段都在元空间。
- [ ] 所有对象一定在堆中。

## 6. 对象创建流程

执行 `new Product()` 时的主要步骤：

1.判断类是否已经被加载、连接和初始化
2.在堆中分配空间
3.赋予默认值
4.设置对象头
5.调用构造方法，完成显式初始化

为什么先设置字段默认值，再执行构造方法：

>保证对象在堆内存不包含未初始化的随机数据
