## 3. 类生命周期

```text
加载 -> 连接（验证、准备、解析）-> 初始化 -> 使用 -> 卸载
```

| 阶段 | 主要做什么                    | 为什么需要                                                      |
| --- |--------------------------|------------------------------------------------------------|
| 加载 | 加载.class字节码并生成class对象    | .class 文件只是外部字节数据，JVM 要先把它转换为运行时可识别的类结构                    |
| 验证 | 验证字节码的正确和安全              | 字节码可能来自网络、插件或动态生成代码。JVM 不能直接执行不可信或结构错误的字节码，否则可能破坏 JVM 运行安全 |
| 准备 | 为类变量分配空间和赋予默认值           | 先让类变量拥有确定的初始状态，后续初始化阶段才能稳定执行开发者定义的赋值逻辑                     |
| 解析 | 把符号引用转为直接引用              | 编译时只知道类名、方法名、方法描述；真正运行时才结合类加载器、继承关系等信息确定目标                 |
| 初始化 | 为类变量赋予真正的值和执行静态代码块       | 初始化阶段才执行你写的业务初始化代码                                         |
| 使用 | 创建对象、调用方法、访问类成员等正常运行行为   |                                                            |
| 卸载 | 类加载器、类及其相关对象都不可达时，类才可能卸载 | 避免OOM                                                      |

我的总结：

>类的加载过程分为：加载、验证、准备、解析、初始化、使用和卸载

## 4. 准备与初始化

代码示例：

```java
static int count = 10;
```

准备阶段后的值：

>0

初始化阶段后的值：

>10

两者核心区别：

>准备阶段只为类变量赋默认值，初始化才会执行类变量显式赋值

需要注意的边界：

- [ ] 准备阶段处理的是类变量，而不是实例字段。
- [ ] `static final int MAX = 10` 这类编译期常量可能在准备阶段就具有最终值。
- [ ] 初始化阶段执行静态字段显式赋值和 `static` 代码块。

## 5. 类初始化触发时机

会触发类初始化：

- [ ] `new` 创建对象。
- [ ] 访问非编译期常量的静态字段。
- [ ] 调用静态方法。
- [ ] `Class.forName()` 默认初始化目标类。
- [ ] 启动主类。

通常不会触发定义类初始化：

- [ ] 访问编译期常量。
- [ ] 通过子类访问定义在父类中的静态字段。
- [ ] 获取类字面量，例如 `Animal.class`。

我的理解：

>创建对象、访问非编译期常量的静态字段、调用静态方法、反射主动加载、启动主类可以触发初始化

## 6. 父子类初始化顺序

访问：

```java
Child.value
```

初始化结果：

>Parent初始化

访问：

```java
Child.childValue
```

初始化结果：

>先Parent初始化，再Child初始化

原因：

>子类初始化必须在父类完成初始化之后


输出结论：

>访问编译期常量静态字段不会触发初始化，必须先完成父类初始化再完成子类初始化，类主动加载可以触发初始化

## 8. 90 秒口述题

### 8.1 JVM 类加载过程有哪些阶段？

我的回答：

>类加载过程包括加载、连接、初始化、使用和卸载；连接又包含验证、准备和解析。准备阶段为类变量分配空间并赋默认值，初始化阶段执行静态变量显式赋值和 static 代码块。解析负责将运行时常量池中的符号引用关联到实际类、字段和方法。这样 JVM 能在执行前保证字节码安全，并按需把类转换成可运行的运行时结构

### 8.2 准备阶段和初始化阶段有什么区别？

我的回答：

>准备阶段只是为类变量分配空间和赋默认值，初始化阶段才会执行类变量的显式赋值和静态代码块
