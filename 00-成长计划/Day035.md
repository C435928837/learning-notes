## 2. DTO 是什么

DTO（Data Transfer Object，数据传输对象）用于接口层接收和返回数据。

```text
前端 JSON
  ↓
请求 DTO
  ↓
Service 处理业务
  ↓
数据库 Entity / 数据表
  ↓
响应 DTO
  ↓
前端 JSON
```

DTO 不应直接等同于数据库 Entity。

数据库对象可能包含：

```text
id
createdAt
updatedAt
deleted
内部状态字段
```

这些字段不应该由前端随意传入，也不一定需要返回给前端。

## 3. `record` 的作用

`record` 适合 DTO、值对象等主要承载数据的类。

```java
public record ProductResponse(
        String productCode,
        String productName,
        BigDecimal price
) {
}
```

编译器会自动生成：

- `private final` 字段
- 全参构造器
- 同名访问方法，例如 `productCode()`
- `equals()`
- `hashCode()`
- `toString()`

DTO 中使用：

```java
public record CreateProductRequest(
        String productCode,
        String productName,
        BigDecimal price
) {
}
```

注意：`record` 的引用不可重新赋值，但字段内部如果持有可变集合，集合内容仍可能被修改。

## 4. 参数校验

### 4.1 校验依赖

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-validation</artifactId>
</dependency>
```

### 4.2 新增商品请求 DTO

```java
public record CreateProductRequest(

        @NotBlank(message = "商品编码不能为空")
        @Size(max = 20, message = "商品编码不能超过 20 个字符")
        String productCode,

        @NotBlank(message = "商品名称不能为空")
        @Size(max = 50, message = "商品名称不能超过 50 个字符")
        String productName,

        @NotNull(message = "商品价格不能为空")
        @DecimalMin(value = "0.01", message = "商品价格必须大于 0")
        BigDecimal price
) {
}
```

常用注解：

| 注解 | 作用 |
| --- | --- |
| `@NotNull` | 不能为 `null` |
| `@NotBlank` | 字符串不能为 `null`、空字符串或只有空格 |
| `@Size` | 字符串、集合长度范围 |
| `@Min` / `@Max` | 整数范围 |
| `@DecimalMin` | 小数最小值 |
| `@Pattern` | 正则格式校验 |

金额使用 `BigDecimal`，避免 `double` 精度问题。

### 4.3 Controller 中触发校验

```java
@PostMapping
public ResponseEntity<ApiResponse<ProductResponse>> createProduct(
        @Valid @RequestBody CreateProductRequest request
) {
    ProductResponse product = productService.createProduct(request);

    return ResponseEntity
            .status(HttpStatus.CREATED)
            .body(ApiResponse.success(product));
}
```

流程：

```text
HTTP JSON 请求
  ↓
Spring 转换为 CreateProductRequest
  ↓
@Valid 执行校验
  ↓
校验失败：不进入 Controller 方法
校验成功：调用 ProductService
```

## 5. 统一响应结构

```java
public record ApiResponse<T>(
        int code,
        String message,
        T data
) {

    public static <T> ApiResponse<T> success(T data) {
        return new ApiResponse<>(0, "success", data);
    }

    public static ApiResponse<Void> failure(
            int code,
            String message
    ) {
        return new ApiResponse<>(code, message, null);
    }
}
```

成功响应：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "productCode": "P002",
    "productName": "Java 面试指南",
    "price": 99.00
  }
}
```

统一响应结构负责应用层格式统一；HTTP 状态码表达协议层结果，两者应同时保留。

| 场景 | HTTP 状态码 | 业务 code |
| --- | --- | --- |
| 创建成功 | `201` | `0` |
| 参数错误 | `400` | `40001` |
| 商品不存在 | `404` | `40401` |
| 商品编码重复 | `409` | `40901` |
| 系统异常 | `500` | `50000` |

## 6. 业务异常与全局异常处理

### 6.1 业务异常

```java
public class BusinessException extends RuntimeException {

    private final int code;
    private final HttpStatus status;

    public BusinessException(
            int code,
            HttpStatus status,
            String message
    ) {
        super(message);
        this.code = code;
        this.status = status;
    }

    public int getCode() {
        return code;
    }

    public HttpStatus getStatus() {
        return status;
    }
}
```

商品编码重复时：

```java
throw new BusinessException(
        40901,
        HttpStatus.CONFLICT,
        "商品编码已存在"
);
```

### 6.2 全局异常处理器

```java
@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ResponseEntity<ApiResponse<Void>> handleValidation(
            MethodArgumentNotValidException e
    ) {
        String message = e.getBindingResult()
                .getFieldErrors()
                .stream()
                .findFirst()
                .map(DefaultMessageSourceResolvable::getDefaultMessage)
                .orElse("参数校验失败");

        return ResponseEntity.badRequest()
                .body(ApiResponse.failure(40001, message));
    }

    @ExceptionHandler(BusinessException.class)
    public ResponseEntity<ApiResponse<Void>> handleBusiness(
            BusinessException e
    ) {
        return ResponseEntity.status(e.getStatus())
                .body(ApiResponse.failure(e.getCode(), e.getMessage()));
    }

    @ExceptionHandler(Exception.class)
    public ResponseEntity<ApiResponse<Void>> handleUnknown(Exception e) {
        // 生产环境记录完整异常日志
        return ResponseEntity.status(HttpStatus.INTERNAL_SERVER_ERROR)
                .body(ApiResponse.failure(50000, "系统繁忙，请稍后再试"));
    }
}
```

## 7. CloudMall 新增商品流程

```text
POST /api/products
  ↓
ProductController 接收 JSON
  ↓
@Valid 校验 CreateProductRequest
  ↓
ProductService 判断商品编码是否重复
  ↓
ProductRepository 写入 H2 products 表
  ↓
正常：返回 HTTP 201 + ApiResponse.success
异常：GlobalExceptionHandler 返回统一错误响应
```

### 验证请求

```http
POST /api/products
Content-Type: application/json

{
  "productCode": "P002",
  "productName": "Java 面试指南",
  "price": 99.00
}
```

验证结果：

- 首次创建：成功，返回 `201`。
- 同一编码再次创建：抛出业务异常，返回 `409`。
- 空编码或价格为 `0`：参数校验失败，返回 `400`。

## 8. 当前 Demo 的生产边界

- “先查询是否重复，再插入”无法独自解决并发重复问题。
- 数据库唯一约束才是最终兜底。
- 生产中应捕获 `DuplicateKeyException` 或 `DataIntegrityViolationException`，统一转换为 `40901`。
- 当前商品查询仍是模拟数据；后续应让查询接口读取 `products` 表，形成读写闭环。
- 未知异常应在服务端记录完整日志，但不向客户端暴露堆栈与内部实现细节。

## 9. 面试表达

### 为什么使用 DTO，而不是直接暴露 Entity？

DTO 用于定义接口契约，可以限制前端可传入和可看到的字段，避免数据库内部字段、敏感字段和审计字段被直接暴露；同时接口演进不会直接影响数据库结构。

### `@Valid` 校验失败后发生什么？

Spring 将 JSON 转换为请求 DTO 后执行校验。校验失败时不会进入 Controller 方法，而是抛出 `MethodArgumentNotValidException`，由全局异常处理器转换为统一的 `400` 响应。

### 为什么需要全局异常处理？

全局异常处理可以集中处理参数校验异常、业务异常和未知异常，避免每个 Controller 重复编写 `try-catch`，并统一响应格式和 HTTP 状态码。
