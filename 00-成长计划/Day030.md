## 二、闭卷复盘结果

### 1. String 为什么不可变

```text
实现方式：
String 的 value 使用 private final 修饰，引用不能指向新的底层数组；
String 不对外暴露可修改的底层数组，也没有修改自身内容的方法；
concat、replace 等操作会返回新的 String 对象。

收益：
多个线程可以安全共享同一个 String；
字符串常量池可以复用相同字面量，节省内存；
hashCode 可以缓存，作为 HashMap key 时更稳定；
类名、URL、数据库地址等信息不容易被意外篡改。
```

### 2. HashSet 为什么能去重

```text
HashSet 底层基于 HashMap 实现，元素作为 key，value 是内部固定占位对象。

hashCode：
计算哈希值，帮助 HashMap 定位桶。

equals：
当对象进入同一个桶后，判断两个对象是否逻辑相等。

契约：
equals 为 true 的两个对象，hashCode 必须相同。

若只重写 equals：
逻辑相等的 Product 可能因为默认 hashCode 不同而落入不同桶；
HashSet 可能同时保存两个相同 code 的 Product；
使用新的相同 code Product 查询 contains 也可能失败。
```

### 3. ArrayList 与 LinkedList 选型

```text
ArrayList：
基于数组实现，随机访问 O(1)，尾部追加和删除通常 O(1)；
中间插入和删除需要移动元素，时间复杂度 O(n)；
内存连续，CPU 缓存友好，普通业务默认优先选择。

LinkedList：
基于双向链表实现，随机访问 O(n)；
只有已定位节点后，插入和删除才是 O(1)；
按下标插入或删除仍需要遍历定位，整体通常是 O(n)；
节点对象多，内存开销大，遍历缓存不友好。

队列和栈：
通常优先使用 ArrayDeque，而不是 LinkedList。
```

### 4. synchronized 与 ReentrantLock

```text
synchronized：
适合简单的 JVM 内互斥场景；
异常退出时会自动释放锁。

ReentrantLock：
适合需要 tryLock 超时获取、lockInterruptibly 可中断获取、
公平锁或多个 Condition 等待队列的场景；
必须在 finally 中调用 unlock() 手动释放锁。
```

### 5. ThreadLocal 为什么必须 remove

```text
ThreadLocalMap 的 key 使用弱引用：
业务代码不再持有 ThreadLocal 对象时，key 可以被 GC 回收。

但 key 变为 null 后：
线程池工作线程仍然存活；
ThreadLocalMap 中的 value 可能继续存在；
长期累积可能造成内存泄漏；
线程复用还可能造成请求上下文污染。

因此任务结束后必须在 finally 中调用 remove()，
主动删除当前线程中的 key-value 条目。
```

### 6. CompletableFuture 商品详情并行查询

```text
商品信息、库存、优惠信息使用 supplyAsync(..., 自定义线程池) 并行查询；
通过 allOf 或 thenCombine 汇总结果。

使用自定义线程池的原因：
业务隔离；
线程数量和队列容量可控；
避免阻塞任务占满 ForkJoinPool.commonPool；
便于通过线程名称排查问题。

异常时：
使用 handle() 返回默认库存、默认优惠或降级标记，
保证详情页核心商品信息仍可返回。
```

## 三、CloudMall 秒杀库存场景

```text
问题：
多实例环境中各 JVM 内存独立，
synchronized 和 AtomicInteger 只能保证单 JVM 内线程安全，
不能防止全局超卖。

方案：
将预热后的库存放入 Redis；
通过 Lua 脚本原子执行“判断库存大于 0 -> 库存减 1”；
扣减成功后创建订单或发送消息，由后续流程持久化。

原理：
Lua 脚本在 Redis 服务端原子执行，
多个请求不会在“判断库存”和“扣减库存”之间交错执行。

边界：
Redis 扣库存成功不代表订单一定创建成功；
需要订单幂等、防重复下单；
订单创建或消息处理失败时需要库存回滚、失败补偿或对账；
数据库可使用 stock > 0 的条件更新作为最终兜底。
```

注意：

```text
Redis INCR 适合商品浏览量等递增计数；
库存扣减应使用原子“判断后扣减”逻辑，不能只执行 DECR。
```
