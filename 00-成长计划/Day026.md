## 三、四种引用

### 1. 回收强度

```text
强引用 > 软引用 > 弱引用 > 虚引用
```

前提：对象没有被更强的引用链持有。

| 类型 | 对应类 | 回收时机 | 典型场景 |
|---|---|---|---|
| 强引用 | 普通变量引用 | 只要强引用存在，就不会回收 | 普通业务对象 |
| 软引用 | `SoftReference` | 内存紧张时可能回收 | 内存敏感的临时数据 |
| 弱引用 | `WeakReference` | 只剩弱引用时，下次 GC 可回收 | `WeakHashMap`、对象关联信息 |
| 虚引用 | `PhantomReference` | 不影响对象回收 | 资源回收跟踪 |

### 2. 强引用

```java
Product product = new Product("P001");
```

`product` 是强引用。只要它仍然指向对象，即使发生 GC，对象也不会被回收。

### 3. 软引用

```java
SoftReference<Product> softReference =
        new SoftReference<>(new Product("P002"));
```

软引用对象在内存充足时通常会保留，在内存紧张时 JVM 可以回收。

边界：

- 软引用的回收时机不精确，受 JVM 和内存压力影响。
- 生产缓存仍应具备容量上限、过期时间和淘汰策略。
- 不应把软引用当作正式缓存的唯一实现方式。

### 4. 弱引用

```java
WeakReference<Product> weakReference =
        new WeakReference<>(product);
```

当对象只剩弱引用、没有强引用时，下一次 GC 可以回收对象。

```java
product = null;
```

回收后：

```java
weakReference.get(); // 返回 null
```

`WeakHashMap` 以弱引用持有 key，适合对象关联的临时元数据。注意：value 不应反向强引用 key，否则 key 仍可能无法回收。

### 5. 虚引用与引用队列

```java
ReferenceQueue<Product> queue = new ReferenceQueue<>();

PhantomReference<Product> phantomReference =
        new PhantomReference<>(product, queue);
```

虚引用特点：

- `phantomReference.get()` 永远返回 `null`。
- 虚引用不能用于继续访问对象。
- 对象进入可回收阶段后，对应虚引用会进入 `ReferenceQueue`。
- 主要用于底层资源回收跟踪；业务中通常优先使用 `Cleaner` 等 JDK 机制。

## 四、ThreadLocal 与弱引用

`ThreadLocalMap` 的 key 使用弱引用：

```text
WeakReference<ThreadLocal<?>>
```

其作用是：当业务代码不再持有 `ThreadLocal` 对象时，key 可以被 GC 回收。

但 key 被回收后，可能出现：

```text
key = null
value 仍被线程池工作线程的 ThreadLocalMap 持有
```

因此，弱引用不能彻底解决泄漏问题。在线程池场景中必须：

```java
try {
    threadLocal.set(context);
    // 业务逻辑
} finally {
    threadLocal.remove();
}
```

`remove()` 的作用是主动删除当前线程中对应的 key-value 条目，避免内存泄漏和请求上下文污染。

## 五、ReferenceDemo

### 1. 实验内容

- 强引用：GC 后对象仍可访问。
- 软引用：GC 后对象可能仍存在，结果不应写死。
- 弱引用：断开强引用后，GC 后通常变为 `null`。
- 虚引用：`get()` 永远为 `null`，并尝试观察其进入 `ReferenceQueue`。

### 2. 注意事项

```text
System.gc() 只是建议 JVM 执行 GC，不保证立即执行。
```

Demo 的目的是理解引用关系，不应用 `System.gc()` 控制生产环境 GC。

### 3. 我的运行结果

```text
强引用：Product{code='P001'}
软引用，GC 前：Product{code='P002'}
软引用，GC 后：Product{code='P002'}
弱引用，GC 前：Product{code='P003'}
弱引用，GC 后：null
虚引用 get()：null
虚引用是否进入引用队列：true
```

### 4. 我的理解

```
引用强度决定对象在 GC 中的存活能力；虚引用不用于访问对象，而是通过引用队列感知回收。

```

## 六、面试口述

### 题目 1：Java 四种引用分别是什么？软引用和弱引用有什么区别？

我的回答：

```
Java 有强、软、弱、虚四种引用。强引用是普通对象引用，只要存在就不会被 GC 回收；
软引用在内存紧张时可能被回收，适合内存敏感的临时数据，但不能替代正式缓存策略；
弱引用在对象只剩弱引用时，下次 GC 可以回收，典型是 WeakHashMap；
虚引用不能通过 get() 获取对象，必须配合 ReferenceQueue 感知对象回收过程。
软引用和弱引用的区别是：软引用通常在内存紧张时才清理，弱引用只要只剩弱引用，在下一次 GC 时就可以清理。
```

### 题目 2：为什么 ThreadLocal 的 key 使用弱引用，为什么仍然必须调用 remove()？

我的回答：

```
ThreadLocalMap 的 key 是弱引用
弱引用只能帮助 ThreadLocal key 被回收
key 变 null 后，value 仍可能被线程池工作线程持有
因此 finally 中调用 remove() 才是避免泄漏和上下文污染的关键

```
