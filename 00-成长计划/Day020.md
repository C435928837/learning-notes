### 2.1 JUC 选型题

1. `synchronized`、`ReentrantLock` 分别适合什么场景？`ReentrantLock` 的额外能力是什么？

我的回答：

>synchronized适合简单的临界区业务处理，ReentrantLock 支持可超时获取锁、可中断获取锁、公平锁和多个 Condition；使用后必须在 finally 中手动 unlock()

2. `Atomicnteger` 为什么只能解决单变量原子性？库存扣减在多实例环境中如何处理？

我的回答：

>AtomicInteger 通过 CAS 保证单 JVM 内单个变量的原子更新，适合本地 Demo 的库存计数。但多实例部署时，每个 JVM 都有独立堆内存，CAS 不能协调全局库存。生产中我会以数据库条件更新作为最终扣减，并将扣库存和创建订单放入事务；同时通过唯一请求号保证订单幂等。

3. `ThreadLocal` 在线程池中为什么必须调用 `remove()`？它会造成哪两类问题？

我的回答：

>ThreadLocal调用remove()是为了避免内存泄漏和上下文污染

4. `ConcurrentHashMap + LongAdder` 为什么适合商品浏览量统计？它的生产边界是什么？

我的回答：

>商品浏览量一般通过商品id和浏览量展示，这就很适合Map存储结构，在多线程环境中ConcurrentHashMap通过桶头锁实现线程安全，LongAdder适合高并发累计，边界是本地内存重启丢失、多实例不共享

5. `CompletableFuture` 适合解决什么问题？为什么商品详情查询要使用自定义线程池？

我的回答：

>CompletableFuture适合解决多任务结果处理或合并的问题，使用自定义线程池是为了可以针对具体业务调整线程，如果都使用默认线程池，容易造成业务阻塞

## 3. CloudMall 面试输出训练

### 3.1 商品浏览量生产方案

场景：多个用户同时浏览商品，需要记录商品浏览量。

我的方案：

>请求同步 Redis INCR 计数，消息队列或定时任务批量落库。普通PV不必强行谈幂等；只有要求“每个事件只统计一次”时才设计事件 ID 去重。

数据一致性与性能取舍：

>浏览量展示允许最终一致，因此优先保证 Redis 高并发写入性能。数据库只做异步批量持久化，避免热点商品频繁更新同一行造成锁竞争。

多实例与重启后的处理方式：

>多个应用实例共用 Redis，不依赖 JVM 本地内存；Redis 开启持久化，并将统计结果异步落库，应用重启不会直接丢失计数。

我会选择：

- [✓] Redis `INCR`
- [✓] 消息队列异步聚合
- [ ] 数据库直接更新
- [ ] 其他：

选择理由：

>Redis INCR 能处理高并发实时计数，消息队列或定时任务负责异步持久化。数据库直接更新只适合低并发场景。

### 3.2 90 秒口述题

题目：请结合 CloudMall，说说你如何处理商品详情页的并行查询和异常降级。

我的口述：

>首先通过CompletableFuture把商品详情的相关信息用多个任务并行查询，最后再把各信息合并汇总成商品的详细信息。如果在查询的过程中遇到异常，handle()返回商品的默认信息或者抛出异常显示查询失败

追问：`CompletableFuture` 能保证库存扣减不超卖吗？为什么？

我的回答：

>不能。CompletableFuture 只负责异步编排，不能保证库存一致性。单 JVM Demo 可以用 AtomicInteger 的 CAS；多实例生产环境要用数据库条件更新或其他共享存储保证全局库存。

## 4. 周末算法题

### 4.1 字母异位词分组

题目：`LeetCode 49. 字母异位词分组`

核心思路：

>记录每个字符出现的次数，如果两个字符串的字符出现次数一样则是异位词

Key 如何设计：

>是按 a-z 固定顺序拼出的 26 个计数值

时间复杂度：

>O(n)，n 是所有字符串的总字符数

空间复杂度：

>O(n)

容易出错的点：

>设计key时要保证字符的排序顺序一致

### 4.2 和为 K 的子数组

题目：`LeetCode 560. 和为 K 的子数组`

核心思路：

>记录每个下标的前缀和，当前前缀和为 prefix 时，若历史前缀和 prefix - k 出现过 count 次，就有 count 个以当前下标结尾、和为 k 的子数组

前缀和 Map 的定义：

> Key：  前缀和
> Value：次数

为什么初始化 `map.put(0, 1)`：

>这样从下标 0 开始、和正好等于 k 的子数组才能被统计到

为什么必须先查询 `prefix - k`，再记录当前 `prefix`：

>防止把空数组也计算进去

时间复杂度：

>O(n)

空间复杂度：

>O(n)
