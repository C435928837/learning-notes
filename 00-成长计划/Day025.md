## 三、垃圾判定

### 1. Java 中的垃圾是什么

垃圾对象指：**后续程序已经无法通过 GC Roots 访问到的对象**。

对象失去业务价值不等于一定能回收；只有它不再被任何 GC Roots 引用链间接持有时，才属于可回收对象。

### 2. 为什么需要清理垃圾

堆内存是有限的。对象持续创建、旧对象长期不回收时，可用内存会不断减少，最终新对象无法分配，可能抛出：

```text
java.lang.OutOfMemoryError: Java heap space
```

GC 的作用是自动回收无用对象占用的内存，让应用能够持续运行。

### 3. 可达性分析

JVM 从一批确定存活的对象开始，即 `GC Roots`，沿引用关系向下搜索：

```text
能从 GC Roots 到达 -> 对象存活，不能回收
不能从 GC Roots 到达 -> 对象不可达，可以回收
```

常见 `GC Roots`：

- 当前活动线程栈帧局部变量表中的引用。
- 类的静态字段引用。
- 正在运行的线程对象。
- JNI 本地方法持有的引用。

### 4. 为什么可达性分析能处理循环引用

```text
GC Roots  ×-->  A <--> B
```

即使 `A` 与 `B` 相互引用，只要没有 GC Roots 能进入这个引用圈，二者都不可达，都可以被回收。

引用计数法无法解决该问题：`A` 被 `B` 引用一次，`B` 被 `A` 引用一次，计数都不为 `0`。

## 四、内存泄漏与 OOM

| 对比项 | 内存泄漏 | OOM |
|---|---|---|
| 含义 | 无业务价值的对象仍被引用，GC 无法回收 | JVM 申请内存时没有足够空间 |
| 本质 | 引用链没有断开 | 内存分配失败 |
| 是否必然立刻报错 | 不一定 | 会抛出 `OutOfMemoryError` |
| 二者关系 | 长期积累可能导致 OOM | 不一定由内存泄漏引起 |

### 1. 常见内存泄漏场景

- 静态 `Map`、`List` 只增不删。
- 缓存没有容量上限或过期淘汰。
- 线程池任务结束后遗漏 `ThreadLocal.remove()`。
- 监听器、回调注册后未注销。
- 自定义类加载器被静态变量或线程长期持有，类无法卸载。

### 2. 常见 OOM 类型

| 类型 | 常见原因 |
|---|---|
| `Java heap space` | 大对象、集合持续增长、缓存失控、堆参数过小 |
| `Metaspace` | 动态生成大量类、类加载器无法卸载 |
| `Direct buffer memory` | 堆外直接内存持续占用 |
| `unable to create native thread` | 线程创建过多，系统线程资源不足 |

### 3. CloudMall 场景

- 浏览量缓存的商品 ID 持续增加、下架商品不清理：内存泄漏风险。
- 导出订单时一次性把几百万条订单加载进 `List`：可能出现堆内存峰值过高导致 OOM。

## 五、GcLogDemo

### 1. 实验目标

循环分配短生命周期数组，在有限堆内存下观察 JVM 触发 GC，并确认 GC 前后已使用内存下降。

### 2. JDK 9+ VM options

```text
-Xms32m -Xmx32m -Xlog:gc*
```

日志示例：

```text
GC(0) Pause Young ... 14M->2M(32M)
```

含义：

```text
GC 前使用 14MB -> GC 后剩余 2MB（最大堆为 32MB）
```

### 3. 我的观察结果

- 是否出现 GC 日志：是
- 出现的 GC 类型：G1 的 Young GC
- 一条 GC 前后内存变化：3M->1M(32M)
- 我的理解：循环中的数组在下一轮失去引用；堆空间紧张时，JVM 通过可达性分析确认其不可达并回收

## 六、面试口述

### 题目 1：JVM 如何判断对象是否是垃圾？为什么不采用引用计数法？

我的回答：

```
JVM 从 GC Roots 出发进行可达性分析，无法通过引用链访问到的对象会被判定为可回收对象。常见 GC Roots 包括活动线程栈帧中的局部变量、静态字段和 JNI 引用。引用计数法无法解决循环引用，而可达性分析只关心对象能否从 GC Roots 到达，因此能回收无法进入的循环引用对象

```

### 题目 2：内存泄漏和 OOM 的区别是什么？各举一个 CloudMall 场景。

我的回答：

```
内存泄漏是指对象被长期引用，无业务价值但仍被引用链持有，无法被 GC 回收，一直占用内存空间，场景：ThreadLocal不调用remove()；
OOM是指内存无法再分配新的空间给对象，场景：后台导出全部订单时，一次性把几百万条订单加载到 List<Order> 再生成 Excel。

```
