## 2. 事务是什么

事务是一组数据库操作组成的整体：

> 要么全部成功并提交，要么任一步失败就全部撤销。

CloudMall 下单涉及：

```text
创建订单
  ↓
扣减数据库库存
```

没有事务时，可能出现“订单创建成功，但库存扣减失败”的数据不一致。

使用事务后：

```text
创建订单成功
扣减库存失败
  ↓
订单创建也回滚
```

订单与库存要么一起生效，要么一起失败。

---

## 3. ACID

| 特性 | 含义 | 下单场景 |
| --- | --- | --- |
| 原子性 | 全部成功或全部失败 | 订单与库存一起提交或回滚 |
| 一致性 | 操作前后符合业务规则 | 订单、库存数据保持正确 |
| 隔离性 | 并发事务间相互影响受控制 | 多人下单时避免不合理的中间状态 |
| 持久性 | 已提交数据不会因宕机轻易丢失 | 成功订单能够恢复 |

## 4. `@Transactional` 执行流程

```java
@Transactional
public void createOrder(String productId) {
    orderRepository.save(productId);
    stockRepository.decrease(productId);
}
```

Spring 通过事务代理执行：

```text
调用方
  ↓
OrderService 事务代理
  ↓
开启数据库事务
  ↓
执行 createOrder()
  ↓
正常结束：提交事务
抛出异常：回滚事务
```

事务本质上也是 AOP 的应用，因此必须经过 Spring 代理才会生效。

## 5. 默认回滚规则

默认情况下，以下异常会触发回滚：

- `RuntimeException` 及其子类
- `Error`

```java
@Transactional
public void createOrder(String productId) {
    // 数据库操作
    throw new IllegalStateException("模拟下单失败");
}
```

受检异常默认不回滚：

```java
@Transactional
public void createOrder(String productId) throws Exception {
    throw new Exception("受检异常");
}
```

需要显式指定：

```java
@Transactional(rollbackFor = Exception.class)
public void createOrder(String productId) throws Exception {
    throw new Exception("受检异常");
}
```

## 6. 事务传播行为

### 6.1 `REQUIRED`

默认传播行为。

```java
@Transactional
public void createOrder() {
    stockService.decreaseStock();
}
```

```java
@Transactional(propagation = Propagation.REQUIRED)
public void decreaseStock() {
}
```

如果外层已有事务，内层加入同一个事务：

```text
创建订单事务 T1
  ↓
扣减库存加入 T1
  ↓
订单与库存一起提交或回滚
```

适合：创建订单与扣减数据库库存。

### 6.2 `REQUIRES_NEW`

暂停外层事务，强制创建独立事务：

```java
@Transactional
public void createOrder() {
    auditService.recordLog();
}
```

```java
@Transactional(propagation = Propagation.REQUIRES_NEW)
public void recordLog() {
}
```

```text
订单事务 T1
  ↓
暂停 T1
  ↓
审计日志事务 T2 独立提交
  ↓
恢复 T1
```

适合：操作审计、独立失败记录等允许与主业务独立提交的操作。

不要把订单创建和库存扣减设为 `REQUIRES_NEW`，否则可能出现库存已提交、订单却回滚的数据不一致。

## 7. 事务高频失效场景

| 场景 | 原因 | 解决方式 |
| --- | --- | --- |
| 同类自调用 | `this.method()` 未经过代理 | 拆分到另一个 Bean |
| 手动 `new` 对象 | 不属于 Spring Bean | 使用 Spring 注入 |
| 吞掉异常 | 方法正常返回，事务会提交 | 继续抛出异常或标记回滚 |
| 抛出受检异常 | 默认不回滚 | 配置 `rollbackFor` |
| `private/final/static` 方法 | 无法被代理正常增强 | 使用非 `final` 的 `public` 实例方法 |
| 异步线程执行 | 新线程不自动继承当前事务 | 原子操作保持同步；异步使用最终一致性 |
| 混用 Redis、MQ、远程调用 | 本地数据库事务不能自动覆盖它们 | 幂等、消息、补偿、回滚、对账 |

## 8. H2 回滚 Demo

### 8.1 表结构

```sql
CREATE TABLE product_stock (
    product_id VARCHAR(20) PRIMARY KEY,
    stock INT NOT NULL
);

CREATE TABLE orders (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    product_id VARCHAR(20) NOT NULL
);

INSERT INTO product_stock(product_id, stock) VALUES ('P001', 10);
```

### 8.2 事务方法

```java
@Transactional
public void createOrder(String productId) {
    jdbcTemplate.update(
            "INSERT INTO orders(product_id) VALUES (?)",
            productId
    );

    jdbcTemplate.update(
            "UPDATE product_stock SET stock = stock - 1 WHERE product_id = ?",
            productId
    );

    throw new RuntimeException("模拟下单失败");
}
```

### 8.3 验证结果

异常后查询 H2 数据库：

```text
捕获异常：模拟下单失败
订单数量：0
P001 库存：10
```

结论：订单插入与库存扣减都已回滚，事务生效。

### 8.4 生产库存扣减补强

本次 Demo 重点是验证事务回滚。生产环境还需要避免库存减为负数：

```sql
UPDATE product_stock
SET stock = stock - 1
WHERE product_id = ?
  AND stock > 0
```

并检查影响行数：为 `0` 时说明库存不足，应抛出异常触发事务回滚。

## 9. 本地事务边界

`@Transactional` 管理的是同一数据库事务中的操作。

它不能自动保证：

```text
数据库创建订单 + Redis Lua 扣库存
```

的一致性。

Redis 扣库存成功但订单创建失败时，需要结合：

- 订单幂等
- 失败补偿
- 库存回滚
- 消息可靠投递
- 定期对账
- 数据库条件更新兜底

## 10. 面试表达

### 什么是事务？

事务是一组数据库操作的原子执行单元，要么全部成功提交，要么任一步失败就全部回滚。以订单创建和库存扣减为例，使用事务可以避免只创建订单或只扣减库存造成的数据不一致。

### `@Transactional` 如何生效？

Spring 通过 AOP 为事务方法创建代理。调用经过代理时，Spring 在方法执行前开启事务，正常结束时提交，出现符合回滚规则的异常时回滚。

### 默认哪些异常会回滚？

默认会回滚 `RuntimeException` 和 `Error`。受检异常需要通过 `rollbackFor` 显式配置。

### 为什么同类自调用会导致事务失效？

事务依赖 Spring 代理。类内部使用 `this.方法()` 调用时，没有经过代理对象，因此事务增强通常不会生效。
