## 2. JdbcTemplate

`JdbcTemplate` 是 Spring 对 JDBC 的封装，用于执行 SQL、绑定参数和处理结果。

常用方法：

| 方法 | 作用 |
| --- | --- |
| `update()` | 执行新增、修改、删除 SQL，返回影响行数 |
| `queryForObject()` | 查询单个结果，例如数量、单行对象 |
| `query()` | 查询多行结果，映射为对象集合 |

示例：

```java
jdbcTemplate.update(
        "INSERT INTO products(product_code, product_name, price) VALUES (?, ?, ?)",
        request.productCode(),
        request.productName(),
        request.price()
);
```

`?` 是 SQL 占位符，参数由 `JdbcTemplate` 绑定，不应通过字符串拼接用户输入，避免 SQL 注入风险。

## 3. 查询真实商品数据

Repository 根据商品编码查询 `products` 表：

```java
public Optional<ProductResponse> findByCode(String productCode) {
    return jdbcTemplate.query(
                    """
                    SELECT product_code, product_name, price
                    FROM products
                    WHERE product_code = ?
                    """,
                    (resultSet, rowNum) -> new ProductResponse(
                            resultSet.getString("product_code"),
                            resultSet.getString("product_name"),
                            resultSet.getBigDecimal("price")
                    ),
                    productCode
            )
            .stream()
            .findFirst();
}
```

Service 判断是否存在：

```java
public ProductResponse getProduct(String productCode) {
    return productRepository.findByCode(productCode)
            .orElseThrow(() -> new BusinessException(
                    40401,
                    HttpStatus.NOT_FOUND,
                    "商品不存在"
            ));
}
```

Controller 返回统一响应：

```java
@GetMapping("/{productCode}")
public ApiResponse<ProductResponse> getProduct(
        @PathVariable String productCode
) {
    return ApiResponse.success(productService.getProduct(productCode));
}
```

## 4. 商品唯一约束

商品表中：

```sql
CREATE TABLE products (
    product_code VARCHAR(20) PRIMARY KEY,
    product_name VARCHAR(50) NOT NULL,
    price DECIMAL(10, 2) NOT NULL
);
```

`product_code` 是主键，因此数据库保证同一个编码只能插入一次。

应用层可以先检查，提高错误提示的可读性：

```java
if (productRepository.existsByCode(request.productCode())) {
    throw new BusinessException(
            40901,
            HttpStatus.CONFLICT,
            "商品编码已存在"
    );
}
```

但不能只依赖“先查再插”：

```text
请求 A 查询：P002 不存在
请求 B 查询：P002 不存在
请求 A 插入成功
请求 B 插入时违反数据库唯一约束
```

因此数据库唯一约束才是并发场景下的最终兜底。

## 5. 数据库重复异常处理

当并发请求绕过应用层预检查时，数据库会抛出 `DataIntegrityViolationException`。

全局异常处理器统一转换为 `409`：

```java
@ExceptionHandler(DataIntegrityViolationException.class)
public ResponseEntity<ApiResponse<Void>> handleDataIntegrityViolation(
        DataIntegrityViolationException e
) {
    return ResponseEntity
            .status(HttpStatus.CONFLICT)
            .body(ApiResponse.failure(40901, "商品编码已存在"));
}
```

这样无论是应用层预检查，还是数据库唯一约束触发的重复，都返回一致结果：

```json
{
  "code": 40901,
  "message": "商品编码已存在",
  "data": null
}
```

## 7. 面试表达

### 为什么不能只使用“先查再插”防止重复数据？

先查再插不是原子操作。高并发下多个请求都可能在查询阶段得到“不存在”，随后同时插入。因此应用层预检查只能改善提示，数据库唯一约束才是最终数据一致性保障。

### JdbcTemplate 如何避免 SQL 注入？

使用 `?` 占位符和参数绑定。SQL 结构与用户输入分离，用户输入不会被当作 SQL 语法执行，因此不能通过拼接特殊字符串改变 SQL 含义。

### 查询不到商品为什么返回 404，而不是 200 加 null？

`404` 明确表达目标资源不存在；`200 + null` 会让调用方难以区分接口成功但无数据、数据异常或资源不存在。HTTP 状态码应正确表达协议层结果。
