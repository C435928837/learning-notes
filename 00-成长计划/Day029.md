## 二、JVM 高频复盘

### 1. JVM 运行时数据区

线程私有：

```text
程序计数器：记录当前线程下一条要执行的字节码指令地址。
虚拟机栈：由栈帧组成，包含局部变量表、操作数栈、动态链接和方法返回地址。
本地方法栈：为本地方法执行服务。
```

线程共享：

```text
堆：主要存放对象和数组。
方法区：存放类元数据、运行时常量池、方法和字段描述等；JDK 8 HotSpot 中类元数据主要由元空间实现。
```

### 2. 类加载与初始化

```text
加载
-> 验证
-> 准备
-> 解析
-> 初始化
-> 使用
-> 卸载
```

```java
class Demo {
    static int count = 10;
    static final int MAX = 10;
}
```

```text
准备阶段：
count = 0
MAX = 10

初始化阶段：
count = 10
执行静态代码块
```

`MAX` 是编译期常量，在准备阶段通过 `ConstantValue` 赋值；普通静态变量 `count` 的显式赋值发生在初始化阶段。

### 3. 静态字段访问与初始化

```java
System.out.println(Child.MAX);
System.out.println(Child.value);
System.out.println(Child.childValue);
```

输出顺序：

```text
8
Parent 初始化
10
Child 初始化
20
```

关键结论：

```text
访问编译期常量 Child.MAX 不触发初始化。
访问 Child.value 实际访问的是 Parent 声明的静态字段，只初始化 Parent。
访问 Child.childValue 时，先初始化 Parent，再初始化 Child。
```

类初始化必须整体完成后，外层代码才会读取并打印静态字段。

### 4. 对象创建与垃圾回收

```java
Product product = new Product("P001");
```

执行链路：

```text
Product 类被加载、验证、准备、解析和初始化
-> 堆中为 Product 对象分配空间
-> 对象字段赋默认值
-> 设置对象头
-> 执行字段显式赋值和构造方法
-> product 引用存放在当前栈帧的局部变量表
```

```java
product = null;
```

```text
当前栈帧不再持有该对象引用。
如果没有其他 GC Roots 引用链能够到达该对象，
JVM 通过可达性分析将其判定为不可达、可回收对象。
是否立刻回收由 JVM 的 GC 时机决定。
```

### 5. G1 收集器

```text
G1 将堆划分为多个大小相等的 Region。
新生代、Survivor 和老年代是逻辑角色，不再要求物理连续。
```

```text
并发标记：
老年代占用达到阈值后开始；
主体工作与业务线程并发，识别整个堆的存活对象。

Mixed GC：
回收所有新生代 Region，
并选择部分垃圾较多、回收收益高的老年代 Region。
```

初始标记和重新标记仍会有短暂 Stop-The-World 停顿。

## 三、CloudMall 场景题

### 1. 大订单导出导致 Heap OOM

```text
现象判断：
一次性导出几百万条订单，List<Order> 在导出完成前持续持有全部订单对象，
导致 GC 无法回收；这是堆内存峰值过高，不一定是内存泄漏。

证据排查：
查看 Full GC 频率、GC 前后堆和老年代是否下降；
观察导出期间堆使用趋势；
保留 Heap Dump，分析占用内存最多的对象和到 GC Roots 的引用链。

代码改造：
使用分页、游标或流式查询；
分批读取、分批写入 Excel；
已写入的数据及时断开持有；
大导出改为异步任务，并限制并发导出数量。
```

### 2. 插件热加载导致 Metaspace OOM

```text
可能原因：
旧插件对象被静态 Map 缓存；
监听器未注销；
插件线程或定时任务仍在运行；
线程上下文类加载器仍指向旧 ClassLoader。

类卸载条件：
类的实例对象不可达；
Class 对象不可达；
加载该类的 ClassLoader 不可达。

改造：
清理缓存和注册表；
注销监听器；
停止插件任务、线程和定时任务；
恢复线程上下文类加载器；
释放插件实例、Class 对象和 ClassLoader 的引用；
调用 URLClassLoader.close() 关闭 JAR 文件句柄。
```

`URLClassLoader.close()` 只能释放底层资源，不保证类立即卸载；只有旧 ClassLoader 不可达后，相关类和元空间才可能被回收。

## 四、90 秒 JVM 串讲

```text
执行 Product product = new Product("P001") 时，JVM 会先确保 Product 类已经完成加载、验证、准备、解析和初始化。随后 JVM 通常在堆中为对象分配空间，先给字段赋默认值，设置对象头，再执行字段显式赋值和构造方法。

product 是当前方法栈帧局部变量表中的引用，对象本身通常位于堆中。执行 product = null 后，当前栈帧不再持有该对象；如果没有其他 GC Roots 能通过引用链访问该对象，JVM 就会通过可达性分析将它判定为不可达和可回收对象。

如果线上出现 Heap OOM 或频繁 Full GC，我会先看 GC 日志和堆内存趋势，确认 GC 后老年代是否下降；再保留 Heap Dump，分析占用内存最多的对象及其到 GC Roots 的引用链，最后定位缓存、ThreadLocal、批量查询、大对象或类加载器等具体问题。
```
